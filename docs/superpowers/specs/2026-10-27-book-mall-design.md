# 图书商城本地离线版设计

日期：2026-10-27

## 意图与背景

这是一个面向 Android 课程期末展示的本地图书商城。目标是让评审可以完整走通“浏览图书 → 查看详情 → 加入购物车 → 提交订单 → 查看订单”的买家流程，同时能看到本地数据库、增删改查、页面跳转和基础界面设计。

当前仓库是空的 Android 应用骨架，包名为 `com.yzc.bookmall`，使用 Java 11、XML 布局、AppCompat 和 Material Components，尚未创建启动 Activity 或业务代码。

## 目标

- 提供一个不依赖网络的可运行商城演示。
- 支持用户注册、登录和退出登录。
- 支持首页推荐、分类浏览、关键词搜索和图书详情。
- 支持收藏、加入购物车、修改数量、删除商品和提交订单。
- 支持订单列表和订单详情，订单提交后进入“待发货”，确认收货后变为“已完成”。
- 使用 SQLite 持久化用户、图书、收藏、购物车和订单数据；首次启动自动插入演示数据。
- 界面适合手机竖屏，统一使用 Material 风格，方便课堂演示和截图写报告。

## 非目标

- 第一版不接入网络接口、Firebase、支付平台或真实物流。
- 第一版不实现管理员后台、商品上传、库存管理、优惠券和复杂促销规则。
- 第一版不追求多用户并发、服务端安全或生产级账号体系。
- 图书封面使用项目内置的本地 drawable 资源，不依赖远程图片加载。

## 失败标准

- 需要联网才能完成主流程。
- 首次启动没有可展示的图书数据，或因数据初始化失败无法浏览。
- 用户可以把商品加入购物车，却不能稳定修改数量或提交订单。
- 重启应用后购物车、收藏或订单全部丢失。
- 页面堆叠在一个 Activity 中，导致功能无法解释或课堂演示时难以操作。
- 为了追求真实商城而加入过多功能，最终没有完成可运行的主流程。

## 方案选择

### 方案一：Java + XML + SQLite（已选择）

在现有 Android 工程基础上继续使用 Java 11 和 XML 布局，以 `SQLiteOpenHelper` 封装本地数据库。优点是依赖少、离线稳定、实现速度快，能直接体现数据库课程考点；缺点是需要手动编写表结构、查询和数据映射。

### 方案二：Java + XML + Room + ViewModel

使用 Room 和 ViewModel 做更完整的分层。代码可维护性更好，但需要增加依赖和学习成本；对本次以功能演示为主的期末作业，初始投入较高。

### 方案三：Firebase 或自建接口

把用户、商品和订单放到云端，体验更接近真实商城，但会引入网络、账号配置、接口调试和演示环境风险，也会增加期末作业的不确定性。

选择方案一的原因是：它与当前 Java/XML 工程直接匹配，主流程可以完全离线展示，并且能在有限时间内完成数据库和界面两个方面的评分点。

## 功能范围与页面

### 启动与账号

- 启动页：显示应用名称并进入登录页或首页。
- 登录页：输入用户名和密码；提供登录按钮和注册入口。
- 注册页：输入用户名、密码和确认密码，校验用户名唯一后写入用户表。
- 未登录用户可以浏览首页、分类和详情；收藏、购物车、下单和订单需要登录。

### 首页

首页使用顶部标题和搜索入口，主体包括推荐图书横向区域、分类入口和热门图书列表。点击图书进入详情，点击分类进入分类页，输入关键词进入搜索结果页。

### 分类与搜索

分类页展示文学、科技、历史、艺术、教育等预置分类。搜索页按书名、作者或分类名称进行模糊查询，空结果显示明确的空状态提示。

### 图书详情

展示封面、书名、作者、出版社、价格、库存和简介。用户可收藏或取消收藏，并选择数量加入购物车。库存不足时禁止加入超过库存的数量。

### 购物车

展示当前用户的购物车条目，支持勾选、全选、增减数量、删除和计算总价。点击结算进入确认订单页；购物车为空时显示引导状态。

### 提交订单

确认订单页展示选中的图书、数量、总价和可编辑的收货姓名、手机号、地址，并预填演示信息。提交时重新检查所有商品库存；任一商品库存不足则不创建订单并提示用户返回购物车。提交成功后创建订单及订单明细，扣减对应库存，并清理已购买的购物车条目，最后进入订单详情。

### 订单

订单页按时间倒序显示订单号、创建时间、商品摘要、总价和状态。第一版状态固定为“待发货”和“已完成”，提交订单后直接进入“待发货”，订单详情提供本地模拟“确认收货”操作。

### 个人中心

展示当前用户名，提供我的收藏、我的订单、退出登录和清空本地数据入口。清空数据需要二次确认，只清理当前账号的收藏、购物车和订单，保留图书目录及其他账号；完成后清除当前登录状态并返回登录页。

## 数据设计

使用一个 `BookDbHelper` 管理数据库版本和初始化数据。建议表结构如下：

- `users`：`id`、`username`、`password`、`created_at`。
- `categories`：`id`、`name`。
- `books`：`id`、`category_id`、`title`、`author`、`publisher`、`price`、`stock`、`cover_res_id`、`description`、`is_recommended`。
- `favorites`：`id`、`user_id`、`book_id`、`created_at`，并对 `user_id + book_id` 建唯一约束。
- `cart_items`：`id`、`user_id`、`book_id`、`quantity`、`created_at`，并对 `user_id + book_id` 建唯一约束。
- `orders`：`id`、`user_id`、`order_no`、`total_amount_fen`、`status`、`receiver_name`、`receiver_phone`、`receiver_address`、`created_at`。
- `order_items`：`id`、`order_id`、`book_id`、`title_snapshot`、`price_snapshot`、`quantity`、`cover_res_id`。

订单明细保存书名和价格快照，避免图书后续改价影响历史订单。提交订单时使用事务完成库存扣减、订单写入、订单明细写入和购物车清理；任何一步失败都回滚。

## 应用结构

采用多个 Activity 配合少量可复用 Adapter：

- `MainActivity`：底部导航，承载首页、分类、购物车和个人中心四个入口。
- `LoginActivity`、`RegisterActivity`：账号流程。
- `BookDetailActivity`：图书详情和收藏/加购。
- `SearchActivity`：搜索输入和结果列表。
- `CheckoutActivity`：订单确认和提交。
- `OrderListActivity`、`OrderDetailActivity`：订单浏览。
- `FavoriteActivity`：收藏列表。
- `BookAdapter`、`CartAdapter`、`OrderAdapter`：列表展示。
- `SessionManager`：保存当前登录用户 ID 和用户名。
- `BookDbHelper`：数据库创建、升级、初始化和 CRUD 查询。

页面之间通过 Intent 传递主键 ID，列表刷新通过 `onResume()` 重新查询数据库，确保从详情页返回后收藏、购物车和订单状态及时更新。金额统一使用人民币，数据库中的价格和订单总额按“分”保存为整数，界面以 `¥` 格式化显示，避免浮点数计算误差。

## 界面与交互约定

- 使用浅色 Material 风格，主色采用暖橙或深蓝，突出书籍和价格。
- 列表项统一包含封面、标题、作者、价格和操作入口。
- 所有空列表、输入错误、库存不足和数据库失败都给出用户可理解的提示。
- 删除、清空数据和提交订单等不可逆操作使用确认对话框。
- 适配常见手机竖屏，优先保证 360dp 到 411dp 宽度下的布局不溢出。
- 首次启动预置至少 10 本图书、5 个分类和一个演示账号提示，确保打开应用就能展示内容。
- 使用 `SharedPreferences` 保存当前用户 ID；应用冷启动时保持登录并进入首页，只有用户主动退出或清空当前账号数据后才返回登录页。

## 验收标准

1. 安装并首次启动后，首页能展示分类和图书。
2. 可以注册新账号、登录、退出并重新登录。
3. 可以按分类和关键词找到图书，打开详情查看完整信息。
4. 收藏、取消收藏、加入购物车、修改数量和删除条目均能正常工作。
5. 提交订单后订单列表和订单详情可见，库存减少，已购买购物车条目被清理。
6. 重启应用后登录状态按设计恢复或退出，图书、收藏、购物车和订单数据仍存在。
7. 不联网时主流程仍可完成。
8. `./gradlew assembleDebug` 能成功构建，现有单元测试和基础 Android 测试不因新增代码失败。

## 已确认的实现决策

- 用户登录状态跨应用重启保留，退出登录时清除会话。
- 第一版不实现支付，提交订单后直接进入“待发货”，确认收货后进入“已完成”。
- 收货姓名、手机号和地址在结算页编辑，并写入订单表；不扩展用户表。
- “清空本地数据”只作用于当前账号的收藏、购物车和订单，保留目录和其他账号，完成后退出登录。
- 订单提交前重新校验全部库存；任一商品不足时整体失败并返回购物车。
- 所有价格以人民币展示，数据库按分保存整数。

## 留给实现者的决定

- 具体颜色、图标、封面资源和布局细节由实现者根据 Material 组件和现有资源选择。
- Activity 与数据库类的具体包结构由实现者按可读性决定。
- 订单状态使用“待发货”和“已完成”两个状态；结算页默认填入演示收货信息，具体文案和演示账号由实现者决定。
- 若实现时间有限，优先保证登录、首页、详情、购物车、下单和订单六个主环节，再补收藏、搜索和个人中心细节。
