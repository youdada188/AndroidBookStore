# 03 · 工程结构与资源系统

> **本篇你会学到**：每个文件夹是干嘛的、`R` 类从哪来、图片和文字放哪里、命名为什么带前缀。

---

## 3.1 先看全景

```
BookMall/
├── app/                          ← 唯一的模块
│   ├── build.gradle.kts          ← 模块构建配置
│   ├── proguard-rules.pro        ← 混淆规则（本项目没用上）
│   └── src/
│       ├── main/                 ← 正式代码（最重要）
│       │   ├── AndroidManifest.xml   ← 应用清单
│       │   ├── java/com/yzc/bookmall/  ← Java 源码
│       │   ├── res/              ← 资源（布局、图片、文字、颜色）
│       │   └── assets/           ← 原样打包的文件（JSON）
│       ├── test/                 ← 单元测试（跑在电脑上）
│       └── androidTest/          ← 仪器测试（跑在手机上）
├── build.gradle.kts
├── settings.gradle.kts
├── gradle/
└── docs/                         ← 文档（就是你正在看的）
```

> **`src` 是 source（源码）的缩写。** `main` 是主代码，`test` / `androidTest` 是测试代码。这种目录结构是 Gradle 定好的规矩，不能随便改名字。

## 3.2 Java 源码的包结构：四层分家

```
com/yzc/bookmall/
├── model/      实体类（数据长什么样）
│   ├── Book.java
│   ├── Store.java
│   ├── CartItem.java
│   ├── Order.java
│   ├── OrderItem.java
│   ├── Review.java
│   ├── Address.java
│   ├── Coupon.java
│   ├── Category.java
│   └── ReceiverInfo.java
├── data/       数据读写（从哪存、从哪取）
│   ├── BookDbHelper.java     建表、升级
│   ├── BookRepository.java   所有增删改查
│   └── JsonSeeder.java       首次启动导入 JSON
├── ui/         界面
│   ├── MainActivity.java     等 13 个页面
│   ├── fragment/             4 个 Fragment
│   ├── adapter/              8 个列表适配器
│   ├── widget/StateView.java 自定义控件
│   ├── BaseActivity.java     所有页面的父类
│   └── Ui.java               小工具
└── util/       工具
    ├── SessionManager.java   登录态
    └── FormatUtils.java      金额/时间格式化
```

**为什么要分这四个包？**

用开餐馆打比方：

| 包 | 类比 | 职责 |
|---|---|---|
| `model` | 菜单上的菜名 | 只描述"数据长什么样"，不含任何业务逻辑 |
| `data` | 仓库 + 采购员 | 只管存取数据，不关心界面 |
| `ui` | 前厅服务员 + 餐桌 | 只管展示和交互，不直接写 SQL |
| `util` | 工具箱 | 到处都要用的小工具 |

**这样分的好处**：改界面不用动数据库代码，改数据库不用动界面。第 12 篇会详细讲这个"分层"。

## 3.3 `R` 类：Android 最神奇的东西

代码里到处是 `R.layout.activity_main`、`R.string.app_name`、`R.id.tv_title`。这个 `R` 是什么？

### 它是自动生成的

你在 `res/layout/activity_splash.xml` 建了个布局文件，**编译时** Android 会自动生成一个类：

```java
public final class R {
    public static final class layout {
        public static final int activity_splash = 0x7f0b0001;
    }
    public static final class string {
        public static final int app_name = 0x7f0f0001;
    }
    public static final class id {
        public static final int tv_countdown = 0x7f080042;
    }
}
```

所以 `R.layout.activity_splash` 就是一个 `int` 数字，指向那个布局文件。

> **注意**：`R` 类在 `app/build/generated/` 目录下，**你永远不要手动改它**。改了资源它自动重新生成。

### `R.xxx.yyy` 的三段式

| 写法 | 含义 |
|---|---|
| `R.layout.activity_main` | `res/layout/` 下的 `activity_main.xml` |
| `R.string.app_name` | `res/values/strings.xml` 里的 `<string name="app_name">` |
| `R.id.tv_title` | 布局里 `android:id="@+id/tv_title"` 定义的控件 ID |
| `R.drawable.ic_back` | `res/drawable/` 下的 `ic_back.xml` |
| `R.color.brand_blue` | `res/values/colors.xml` 里的颜色 |
| `R.menu.menu_bottom_nav` | `res/menu/` 下的菜单 |

**规律：`R.资源类型.文件名（不含扩展名）`**。

### `@+id/` 和 `@id/` 的区别

```xml
<TextView android:id="@+id/tv_countdown" />
```

- `@+id/xxx` = **创建**一个新 ID（`+` 表示新增）
- `@id/xxx` = **引用**一个已存在的 ID

第一次定义用 `@+id/`，之后在别处引用用 `@id/`。

## 3.4 `res/` 目录：资源大全

```
res/
├── layout/          28 个布局文件
├── drawable/        30 个矢量图 / 形状
├── drawable-nodpi/  25 张 JPG（书封、书店头图）
├── values/          strings.xml / colors.xml / themes.xml
├── values-night/    夜间模式主题
├── color/           颜色选择器（随状态变色）
├── menu/            底部导航菜单
├── mipmap-anydpi/   启动图标（矢量，兼容旧系统）
├── mipmap-anydpi-v26/ 启动图标（自适应，Android 8+）
└── xml/             备份规则
```

### `values/` 里的三个文件

**`strings.xml` —— 所有文字**

```xml
<string name="app_name">书墨商城</string>
<string name="cart_empty">购物车还是空的，去书店挑一本喜欢的书吧</string>
<string name="stock_format">库存 %1$d</string>
```

> **为什么文字不直接写在布局里？** 三个原因：① 做多语言只需加 `values-en/strings.xml`；② 同一句话多处使用，改一处全变；③ 长文案放布局里会让 XML 很难读。

**`colors.xml` —— 所有颜色**

```xml
<color name="brand_blue">#1E3A5F</color>
<color name="brand_orange">#D97706</color>
<color name="text_primary">#1F2937</color>
<color name="text_secondary">#6B7280</color>
```

> **命名解读**：`brand_blue` = 品牌蓝，`text_primary` = 主要文字色，`text_secondary` = 次要文字色，`text_hint` = 提示文字色。**用"用途"命名而不是用"颜色值"命名**，这样以后把蓝色改成绿色，名字不用变。

**`themes.xml` —— 主题**

```xml
<style name="Theme.BookMall" parent="Theme.MaterialComponents.Light.NoActionBar">
    <item name="colorPrimary">@color/brand_blue</item>
    <item name="colorSecondary">@color/brand_orange</item>
    <item name="android:windowBackground">@color/surface</item>
</style>
```

- `parent` = 继承哪个主题。`Light` 表示固定浅色，`NoActionBar` 表示不要系统自带的标题栏（我们自己做）
- `colorPrimary` = 主色，按钮、选中态默认用它
- `colorSecondary` = 强调色

### `drawable/` 里的三种东西

**① 矢量图标（Vector Drawable）**

```xml
<vector android:width="24dp" android:height="24dp"
        android:viewportWidth="24" android:viewportHeight="24">
    <path android:fillColor="@android:color/white"
          android:pathData="M20,11H7.83l5.59,-5.59L12,4l-8,8 8,8 1.41,-1.41L7.83,13H20v-2z" />
</vector>
```

这就是项目里 `ic_back.xml`（返回箭头）的内容。`pathData` 是一串画图指令，**矢量图放大不糊**，比 PNG 省空间。

**② 形状（Shape）**

```xml
<shape android:shape="rectangle">
    <solid android:color="@color/surface_card" />
    <corners android:radius="14dp" />
    <stroke android:width="1dp" android:color="@color/divider" />
</shape>
```

这是 `bg_search_bar.xml`，画了一个圆角矩形。用它当背景，就有了搜索框的样子。

**③ 选择器（Selector）**

```xml
<selector>
    <item android:state_selected="true">
        <shape><solid android:color="@color/brand_blue" /><corners android:radius="16dp" /></shape>
    </item>
    <item>
        <shape><solid android:color="@color/surface_card" /><corners android:radius="16dp" /></shape>
    </item>
</selector>
```

这是 `bg_chip.xml`。**同一个控件，选中时蓝色、未选中时白色**，靠这个文件自动切换，不用写代码判断。

### `drawable-nodpi/` 是什么

`-nodpi` 是**密度限定符**，意思是"不要根据屏幕密度缩放"。

项目里的书封是固定 76×102dp 显示的，如果系统按密度缩放，同一张图在不同手机上会显示不同大小。加 `-nodpi` 就是告诉系统："原样用，别动。"

> 顺带说下 `dp` 和 `sp`：
> - **`dp`**（density-independent pixel）= 独立像素，**布局尺寸用它**。160dpi 屏幕上 1dp = 1px，高密度屏自动放大。
> - **`sp`**（scale-independent pixel）= 可缩放像素，**文字大小用它**。它会跟随用户在系统设置里调的字号变化。
> - **`px`** = 物理像素，**别用**，不同手机差别巨大。

## 3.5 资源命名规范：前缀不是随便加的

打开 `layout/` 目录，你会看到这样的名字：

```
activity_main.xml          页面布局
activity_splash.xml
fragment_home.xml          Fragment 布局
item_book.xml              列表项布局
view_toolbar.xml           可复用的局部组件
```

打开 `drawable/`：

```
ic_back.xml                图标（icon）
ic_nav_home.xml
bg_chip.xml                背景（background）
bg_round_card.xml
book_001.jpg               图片内容
store_1.jpg
```

**为什么加这些前缀？**

| 前缀 | 含义 | 好处 |
|---|---|---|
| `activity_` | 某个 Activity 的布局 | 一眼知道它配哪个页面 |
| `fragment_` | 某个 Fragment 的布局 | 同上 |
| `item_` | 列表里的一行 | 看到就知道是给 Adapter 用的 |
| `view_` | 可复用小组件 | 表示"这不是整页，是一块" |
| `ic_` | icon 图标 | 和背景图区分开 |
| `bg_` | background 背景 | 同上 |

**想象一下不加前缀**：`main.xml`、`home.xml`、`book.xml`、`back.xml`、`card.xml`……过两个月你自己都分不清哪个是页面、哪个是图标。

> 这套前缀是 Google 官方 Material Design 指南推荐的，也是业界通用做法。

## 3.6 `assets/` 与 `res/` 的区别（重要）

```
app/src/main/assets/seed/
├── stores.json
├── categories.json
├── books.json
└── coupons.json
```

| | `res/` | `assets/` |
|---|---|---|
| 有没有索引 | **有**，每个文件生成一个 `R.xxx` | **没有**，只能按路径字符串读 |
| 能不能被系统适配 | 能（按语言、屏幕、夜间模式自动选） | 不能，原样打包 |
| 怎么读 | `R.string.app_name` | `context.getAssets().open("seed/books.json")` |
| 适合放什么 | 布局、图标、文案、颜色 | JSON、字体、离线网页、数据库文件 |

**为什么 JSON 放 assets？** 因为它是**原始数据文件**，不需要系统帮我们做多语言或分辨率适配，只需要原样读出来解析。

## 3.7 `AndroidManifest.xml`：应用的"身份证"

```xml
<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <application
        android:icon="@mipmap/ic_launcher"
        android:label="@string/app_name"
        android:theme="@style/Theme.BookMall">

        <activity android:name=".ui.SplashActivity" android:exported="true">
            <intent-filter>
                <action android:name="android.intent.action.MAIN" />
                <category android:name="android.intent.category.LAUNCHER" />
            </intent-filter>
        </activity>

        <activity android:name=".ui.LoginActivity" />
        <activity android:name=".ui.MainActivity" />
        <!-- ... 其余 11 个页面 -->
    </application>
</manifest>
```

**四个关键点：**

1. **每个 Activity 都必须在这里登记**，否则 `startActivity` 会崩（报 `ActivityNotFoundException`）
2. `.ui.SplashActivity` 前面的 `.` 是简写，等价于完整包名 `com.yzc.bookmall.ui.SplashActivity`
3. **带 `LAUNCHER` intent-filter 的那个就是启动页**——本项目是 `SplashActivity`
4. `android:exported="true"` 表示"允许外部（比如桌面图标）启动我"。Android 12+ 强制要求：有 intent-filter 的组件必须显式声明这个属性

> **命名解读**：`mipmap` 是 Android 专门放**启动图标**的目录。为什么叫 mipmap 而不是 drawable？因为启动器会在不同缩放级别缓存图标，mipmap 是图形学里"多级纹理"的术语。

## 3.8 一次改动的完整链路（帮你建立直觉）

假设你要把首页标题"书墨商城"改成"书海商城"：

```
① 改 res/values/strings.xml
   <string name="app_name">书海商城</string>
        ↓
② 编译时自动生成 R.string.app_name
        ↓
③ 布局里 android:text="@string/app_name" 自动取到新值
        ↓
④ 代码里 getString(R.string.app_name) 也自动变了
```

**一处改动，全局生效**——这就是资源系统的价值。

## 3.9 本篇小结

- 源码分四层：`model` / `data` / `ui` / `util`
- `R` 类是编译时自动生成的资源索引，不要手改
- `res/` 有索引能被适配，`assets/` 无索引原样打包
- 布局前缀：`activity_` / `fragment_` / `item_` / `view_`
- 图标前缀：`ic_`（图标）、`bg_`（背景）
- 颜色按"用途"命名，不按颜色值命名
- `dp` 用于尺寸，`sp` 用于文字
- Manifest 里必须登记所有 Activity，带 LAUNCHER 的是启动页
