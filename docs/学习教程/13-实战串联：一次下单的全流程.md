# 13 · 实战串联：一次下单的全流程

> **本篇你会学到**：把前面 12 篇的知识串成一条线，从"点去结算"一路追到"确认收货"。
> 这一篇没有新概念，全是**复习和串联**。

## 13.0 场景

用户已经登录，购物车里有 3 本书，现在要下单。

```
购物车 → 勾选 → 去结算 → 选地址 → 用券 → 提交 → 订单详情 → 确认收货 → 评价
```

我们一步一步追代码，每一步都标注**用到了哪一篇的知识**。

`getCartItems` 在 `BookRepository` 里执行这条 SQL：

```sql
SELECT ci.id, ci.user_id, ci.book_id, b.title, b.author,
       b.price_fen, b.cover_res_id, b.stock, ci.quantity
FROM cart_items ci
JOIN books b ON b.id = ci.book_id
WHERE ci.user_id = ?
ORDER BY ci.id DESC
```

**`JOIN` 是什么？** 把两张表按关联字段拼起来查。购物车表只存了 `book_id`，要显示书名和价格就得去 `books` 表取。

**为什么合计用 `int` 而不是 `double`？**

第 09 篇讲过：浮点数有精度问题。`59.00 × 3` 用 double 可能算出 `177.00000000000003`。用分（`5900 × 3 = 17700`）绝对精确。

## 13.3 第 3 步：点"去结算"

```java
private void checkout() {
    if (!session.isLoggedIn()) {
        startActivity(new Intent(requireContext(), LoginActivity.class)
                .putExtra("redirect_tab", "cart"));       // ← 登录后回购物车
        return;
    }

    List<CartItem> selected = adapter.getSelectedItems();
    if (selected.isEmpty()) {
        Ui.toast(requireContext(), R.string.cart_select_hint);
        return;
    }

    long[] ids = new long[selected.size()];
    for (int i = 0; i < selected.size(); i++) ids[i] = selected.get(i).getBookId();

    Intent intent = new Intent(requireContext(), CheckoutActivity.class);
    intent.putExtra(CheckoutActivity.EXTRA_BOOK_IDS, ids);   // ← 只传 ID 数组
    startActivity(intent);
}
```

**三个设计点：**

| 设计 | 原因 | 出自 |
|---|---|---|
| 传 `long[]` 而不是 `List<CartItem>` | Intent 只支持基本类型和数组 | 第 06 篇 |
| 传 `bookId` 而不是 `cartItemId` | 结算页要重新查最新价格和库存 | 第 06 篇 |
| 未登录带 `redirect_tab` | 登录后能回到购物车 | 第 06 篇 |

### ① `loadSelectedItems()`：把 ID 数组还原成对象

```java
private List<CartItem> loadSelectedItems() {
    long[] ids = getIntent().getLongArrayExtra(EXTRA_BOOK_IDS);
    List<CartItem> all = repository.getCartItems(session.getUserId());

    if (ids == null || ids.length == 0) return all;   // 没传就全选

    List<CartItem> selected = new ArrayList<>();
    for (CartItem item : all) {
        for (long id : ids) {
            if (item.getBookId() == id) { selected.add(item); break; }
        }
    }
    return selected;
}
```

**注意**：这里重新查了一遍购物车，而不是用传过来的数据。**因为价格和库存可能已经变了。**

### ③ `computeDeliveryFee()`：多店累加

```java
private int computeDeliveryFee() {
    Set<Long> storeIds = new HashSet<>();
    int total = 0;
    for (CartItem item : items) {
        Book book = repository.getBookById(item.getBookId());
        if (book == null) continue;
        if (!storeIds.add(book.getStoreId())) continue;   // ★ 同一家店只算一次
        Store store = repository.getStoreById(book.getStoreId());
        if (store != null) total += store.getDeliveryFeeFen();
    }
    return total;
}
```

**关键在 `storeIds.add(...)` 的返回值**：

`Set.add()` 返回 `boolean`：
- 添加成功（之前没有）→ 返回 `true`
- 已存在 → 返回 `false`

所以 `if (!storeIds.add(id)) continue;` 的意思是："**如果这家店已经算过了，跳过。**"

**为什么这么设计？** 因为购物车里可能有 3 本书，其中 2 本来自同一家店。配送费应该按**店**算，不是按**书**算。

> 这个技巧叫"**用 Set 去重**"，比写 `if (storeIds.contains(id)) continue; storeIds.add(id);` 少一行。

### ⑤ `findBestCoupon()`：自动选最划算的券

```java
// BookRepository
public Coupon findBestCoupon(long userId, int goodsAmountFen) {
    Coupon best = null;
    for (Coupon coupon : getCoupons(userId)) {
        if (!coupon.isUsable(goodsAmountFen)) continue;      // 门槛不够，跳过
        if (best == null || coupon.getDiscountFen() > best.getDiscountFen()) {
            best = coupon;                                    // 更划算，替换
        }
    }
    return best;
}
```

**这是"打擂台"算法**：先设 `best = null`，遍历时不断挑战，最后留下的就是最优解。

`Coupon.isUsable()`：

```java
public boolean isUsable(int goodsAmountFen) {
    return !used && goodsAmountFen >= thresholdFen;
}
```

**两个条件**：没用过 + 商品金额达到门槛。

## 13.5 第 5 步：金额计算

```java
private void bindAmounts() {
    discountFen = (coupon != null && coupon.isUsable(goodsFen)) ? coupon.getDiscountFen() : 0;
    int payFen = Math.max(0, goodsFen + deliveryFen - discountFen);   // ★

    ((TextView) findViewById(R.id.tv_goods_total)).setText(FormatUtils.formatPrice(goodsFen));
    ((TextView) findViewById(R.id.tv_delivery_fee)).setText(
            deliveryFen == 0 ? "免配送费" : FormatUtils.formatPrice(deliveryFen));

    if (discountFen > 0) {
        discountView.setText("−" + FormatUtils.formatPrice(discountFen) + "（" + coupon.getTitle() + "）");
        discountView.setTextColor(getColor(R.color.brand_orange));
    } else {
        discountView.setText(R.string.checkout_no_coupon);
        discountView.setTextColor(getColor(R.color.text_hint));
    }

    ((TextView) findViewById(R.id.tv_pay_total)).setText(FormatUtils.formatPrice(payFen));
    ((TextView) findViewById(R.id.tv_bottom_total)).setText("实付 " + FormatUtils.formatPrice(payFen));
}
```

**★ `Math.max(0, ...)` 是干什么的？**

防止出现负数。假设商品 50 元、配送费 0、优惠券 60 元（理论上不该发生，但万一数据错了），实付就是 `50 - 60 = -10`。加 `Math.max(0, ...)` 保证最少是 0。

> **防御性编程**：不要假设数据一定正确，**在关键计算处加保护**。这是写代码的好习惯。

## 13.6 插播：`StateView` 是怎么实现的

前面反复用到 `stateView.showLoading()`，现在看看它内部。

**文件**：`ui/widget/StateView.java`

> 下面为了突出主流程，省略了部分 `setVisibility` 和样式设置，完整代码请对照源文件看。

```java
public class StateView extends LinearLayout {
    public static final int LOADING = 0;
    public static final int EMPTY = 1;
    public static final int ERROR = 2;
    public static final int CONTENT = 3;

    private final ProgressBar progressBar;      // 转圈的进度条
    private final TextView messageView;         // 提示文字
    private final MaterialButton retryButton;   // 重试按钮
    private View contentView;                   // 要控制显隐的内容（列表）
    private Runnable retryAction;               // 点重试时执行什么
    private int state = CONTENT;

    public StateView(Context context, AttributeSet attrs) {
        super(context, attrs);
        setOrientation(VERTICAL);
        setGravity(Gravity.CENTER);
        setBackgroundColor(context.getColor(R.color.surface));

        progressBar = new ProgressBar(context);
        addView(progressBar, new LayoutParams(dp(36), dp(36)));

        messageView = new TextView(context);
        messageView.setTextSize(14);
        messageView.setTextColor(context.getColor(R.color.text_secondary));
        addView(messageView, ...);

        retryButton = new MaterialButton(context);
        retryButton.setText(R.string.retry);
        retryButton.setVisibility(GONE);
        addView(retryButton, ...);
        retryButton.setOnClickListener(v -> {
            if (retryAction != null) retryAction.run();
        });
    }

    /** 关联内容视图，切换状态时一并控制可见性 */
    public void bind(View content) {
        this.contentView = content;
        showContent();
    }

    public void showLoading() {
        state = LOADING;
        setVisibility(VISIBLE);
        progressBar.setVisibility(VISIBLE);
        messageView.setText(R.string.loading);
        retryButton.setVisibility(GONE);
        if (contentView != null) contentView.setVisibility(GONE);
    }

    public void showContent() {
        state = CONTENT;
        setVisibility(GONE);                        // ★ 自己隐藏
        if (contentView != null) contentView.setVisibility(VISIBLE);   // 内容显示
    }

    public void showEmpty(String message) {
        state = EMPTY;
        setVisibility(VISIBLE);
        progressBar.setVisibility(GONE);            // 不转圈
        messageView.setText(message);
        retryButton.setVisibility(GONE);            // 空状态不需要重试
        if (contentView != null) contentView.setVisibility(GONE);
    }

    public void showError(String message, Runnable retry) {
        state = ERROR;
        setVisibility(VISIBLE);
        progressBar.setVisibility(GONE);
        messageView.setText(message);
        retryAction = retry;
        retryButton.setVisibility(retry == null ? GONE : VISIBLE);
        if (contentView != null) contentView.setVisibility(GONE);
    }
}
```

### 三个设计要点

**① 它自己就是一个布局（`extends LinearLayout`）**

不用写 XML，全部在构造方法里 `new` 出来。这叫**自定义控件**。

**② `bind(View content)` 建立联系**

```java
stateView.bind(recyclerView);
```

之后每次切状态，`StateView` 会**同时**控制自己列表的显隐：

| 状态 | StateView 自己 | 列表 |
|---|---|---|
| LOADING | 显示 | 隐藏 |
| CONTENT | **隐藏** | 显示 |
| EMPTY | 显示 | 隐藏 |
| ERROR | 显示 | 隐藏 |

**③ `Runnable retryAction` 让重试可用**

```java
stateView.showError("加载失败：" + e.getMessage(), this::load);
```

传一个方法引用进去，用户点"重试"就重新执行 `load()`。**这是把"行为"当参数传**，和第 02 篇讲的 Lambda 是一回事。

### 为什么要统一这个组件

如果每个页面自己写"加载中"的提示，会出现：

- A 页面转圈在中间，B 页面转圈在左上
- C 页面用"加载中…"，D 页面用"正在加载"
- E 页面干脆忘了写空状态

**统一组件 = 统一体验 + 少写重复代码。** 这是工程化的基本思路。

## 13.8 第 7 步：提交订单

```java
private void submit() {
    if (address == null) {
        Ui.toast(this, "请先添加收货地址");
        openAddressPicker();
        return;
    }
    int payFen = Math.max(0, goodsFen + deliveryFen - discountFen);

    new AlertDialog.Builder(this)
            .setTitle(R.string.checkout_confirm_title)
            .setMessage(getString(R.string.checkout_confirm_message, FormatUtils.yuan(payFen)))
            .setNegativeButton(R.string.cancel, null)
            .setPositiveButton(R.string.confirm, (dialog, which) -> doSubmit())
            .show();
}
```

**为什么要二次确认？**

因为下单是**不可逆操作**（虽然能取消订单，但本项目没做）。用户误触直接下单会很不爽。

> **经验法则**：删除、支付、提交订单这类不可逆操作，**都要二次确认**。

```java
private void doSubmit() {
    try {
        long orderId = repository.createOrder(
                session.getUserId(),          // 谁买的
                items,                        // 买什么
                address.toReceiverInfo(),     // 送到哪
                deliveryFen,                  // 配送费
                discountFen,                  // 优惠多少
                coupon == null ? null : coupon.getTitle(),   // 券名（存快照）
                coupon == null ? 0 : coupon.getId());        // 券 ID（标记已用）

        Ui.toast(this, R.string.checkout_success);

        Intent intent = new Intent(this, OrderDetailActivity.class);
        intent.putExtra(OrderDetailActivity.EXTRA_ORDER_ID, orderId);
        startActivity(intent);
        finish();                          // ← 关掉结算页

    } catch (IllegalStateException e) {
        // 业务异常（库存不足等）：提示后返回购物车
        new AlertDialog.Builder(this)
                .setTitle("提交失败")
                .setMessage(e.getMessage())
                .setPositiveButton(R.string.confirm, (dialog, which) -> finish())
                .show();
    } catch (Exception e) {
        Ui.toast(this, "下单失败：" + e.getMessage());
    }
}
```

**两个 `catch` 的区别：**

| 异常类型 | 含义 | 处理 |
|---|---|---|
| `IllegalStateException` | **业务错误**（库存不足、地址为空） | 弹窗说明原因，用户能理解 |
| `Exception` | **系统错误**（数据库异常等） | Toast 提示，用户看不懂细节但知道失败了 |

**为什么要分开？** 因为业务错误要**告诉用户具体原因**（"《活水》库存仅剩 2 本"），系统错误只要说"失败了"就行，说细节用户也看不懂。

## 13.9 第 8 步：`createOrder` 的事务

这是整个项目技术含量最高的部分，第 09 篇详细讲过。这里只回顾骨架：

```java
db.beginTransaction();
try {
    // ① 第一轮：检查库存 + 算钱（只读，不写）
    for (CartItem item : selectedItems) {
        Book current = getBookInTransaction(db, item.getBookId());
        if (current == null) throw new IllegalStateException("图书已下架");
        if (item.getQuantity() > current.getStock()) throw new IllegalStateException("库存不足");
        goodsFen += current.getPriceFen() * item.getQuantity();
    }

    // ② 写订单主表
    long orderId = db.insertOrThrow(TABLE_ORDERS, null, order);

    // ③ 逐条写明细 + 扣库存 + 清购物车
    for (CartItem item : selectedItems) {
        db.insertOrThrow(TABLE_ORDER_ITEMS, null, detail);     // 明细（含快照）
        db.update(TABLE_BOOKS, stock, "id=?", ...);            // 扣库存
        db.delete(TABLE_CART, "user_id=? AND book_id=?", ...); // 清购物车
    }

    // ④ 标记券已用
    db.update(TABLE_USER_COUPONS, used, ...);

    db.setTransactionSuccessful();
    return orderId;
} finally {
    db.endTransaction();      // 没标记成功 → 自动回滚
}
```

**"要么全成功，要么全失败"** —— 这就是事务的价值。

## 13.10 第 9 步：订单详情与确认收货

**文件**：`ui/activity/OrderDetailActivity.java`

```java
private void load() {
    try {
        Order order = repository.getOrder(session.getUserId(), orderId);   // ★ 带 userId
        if (order == null) {
            stateView.showError("订单不存在或无权查看");
            return;
        }
        bind(order);
        stateView.showContent();
    } catch (Exception e) {
        stateView.showError("订单加载失败：" + e.getMessage(), this::load);
    }
}
```

**★ 注意 `getOrder(userId, orderId)` 两个参数**

```sql
SELECT ... FROM orders o WHERE o.user_id = ? AND o.id = ?
```

**必须同时匹配 `user_id`**。如果只按 `order_id` 查，用户改一下 ID 就能看到别人的订单——**这是越权漏洞**。

> **安全原则**：任何"查我的数据"的操作，SQL 里都必须带 `user_id = ?`。

**确认收货：**

```java
View receiptButton = findViewById(R.id.btn_confirm_receipt);
receiptButton.setVisibility(order.isPending() ? View.VISIBLE : View.GONE);
receiptButton.setOnClickListener(v -> {
    repository.confirmReceipt(orderId, session.getUserId());
    Ui.toast(this, R.string.order_receipt_done);
    load();                     // ← 重新加载，状态变成"已完成"

```

```java
public void confirmReceipt(long orderId, long userId) {
    ContentValues v = new ContentValues();
    v.put("status", "已完成");
    dbHelper.getWritableDatabase().update(TABLE_ORDERS, v,
            "id=? AND user_id=? AND status=?",       // ★ 三个条件
            new String[]{String.valueOf(orderId), String.valueOf(userId), "待发货"});
}
```

**★ `AND status = '待发货'` 是干什么的？**

防止重复确认。如果订单已经是"已完成"，这个 `UPDATE` 会影响 0 行，不会出问题。这叫**幂等操作**（执行多次结果一样）。

## 13.11 第 10 步：评价

```java
private void startReview() {
    if (!session.isLoggedIn()) { requireLogin(); return; }

    long userId = session.getUserId();
    if (repository.hasReviewed(userId, bookId)) {
        Ui.toast(this, R.string.review_already);      // 已经评过
        return;
    }
    if (!repository.canReview(userId, bookId)) {
        Ui.toast(this, R.string.review_only_buyer);   // 没买过
        return;
    }
    // 弹窗：RatingBar + EditText
```

**`canReview` 的实现：**

```java
public boolean canReview(long userId, long bookId) {
    if (userId <= 0) return false;
    if (hasReviewed(userId, bookId)) return false;
    try (Cursor c = dbHelper.getReadableDatabase().rawQuery(
            "SELECT 1 FROM orders o JOIN order_items oi ON oi.order_id = o.id " +
            "WHERE o.user_id = ? AND oi.book_id = ? LIMIT 1",
            new String[]{String.valueOf(userId), String.valueOf(bookId)})) {
        return c.moveToFirst();
    }
}
```

**`SELECT 1 ... LIMIT 1` 是什么写法？**

- 不查具体字段，只查常量 `1` —— 因为只关心"有没有"
- `LIMIT 1` —— 找到一条就停，不用扫全表

**这是"存在性查询"的标准优化写法**，比 `SELECT COUNT(*)` 快（不用数完）。
