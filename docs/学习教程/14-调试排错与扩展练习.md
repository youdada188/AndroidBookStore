## 14.1 崩溃了先看哪里：Logcat

Android Studio 底部有一排标签：`Build`、`Run`、`Logcat`、`Debug`…**点 `Logcat`**。

### 日志的五个级别

| 级别 | 方法 | 颜色 | 用在哪 |
|---|---|---|---|
| Verbose | `Log.v()` | 灰 | 最啰嗦的调试信息 |
| Debug | `Log.d()` | 蓝 | 调试用 |
| Info | `Log.i()` | 绿 | 普通信息 |
| Warn | `Log.w()` | 黄 | 警告（能跑但有问题） |
| Error | `Log.e()` | **红** | 错误 |

**项目里用了两个：**

```java
// JsonSeeder：解析失败
Log.e(TAG, "种子数据解析失败，改用最小数据集", e);

// BookDbHelper：列已存在（不算错误）
Log.w(TAG, "列 " + column + " 已存在，跳过", e);
```

> **`TAG` 是什么？** 日志标签，用来过滤。项目里定义为 `private static final String TAG = "JsonSeeder";`，习惯上等于类名。

### 过滤日志

Logcat 顶部有个搜索框，输入：

| 输入 | 效果 |
|---|---|
| `com.yzc.bookmall` | 只看本 App 的日志 |
| `tag:JsonSeeder` | 只看这个 TAG |
| `level:error` | 只看错误 |
| `package:mine` | 只看当前 App（AS 的快捷语法） |

**建议**：先输入 `package:mine level:error`，只看自己的错误。

## 14.2 读懂崩溃堆栈

崩溃时 Logcat 会打出一大段红色文字，长这样：

```
FATAL EXCEPTION: main
Process: com.yzc.bookmall, PID: 12345
java.lang.NullPointerException: Attempt to invoke virtual method
    'java.lang.String com.yzc.bookmall.model.Book.getTitle()'
    on a null object reference
    at com.yzc.bookmall.ui.BookDetailActivity.bindBook(BookDetailActivity.java:142)
    at com.yzc.bookmall.ui.BookDetailActivity.load(BookDetailActivity.java:118)
    at com.yzc.bookmall.ui.BookDetailActivity.access$000(BookDetailActivity.java:25)
    at com.yzc.bookmall.ui.BookDetailActivity$1.run(BookDetailActivity.java:110)
    at android.os.Handler.handleCallback(Handler.java:938)
    at android.os.Looper.loop(Looper.java:246)
    at android.app.ActivityThread.main(ActivityThread.java:8512)
```

### 怎么读（从下往上看还是从上往下看？）

**从上往下读，找到第一个 `at com.yzc.bookmall...` 的那一行。**

```
① 异常类型：java.lang.NullPointerException
② 具体原因：Attempt to invoke ... on a null object reference
             （在一个 null 对象上调用方法）
③ 你的代码位置：BookDetailActivity.bindBook(BookDetailActivity.java:142)   ← 就是这里
```

**下面的 `at android.os.Handler...` 都是系统框架的调用栈，可以忽略。**

### 逐行翻译

| 原文 | 意思 |
|---|---|
| `FATAL EXCEPTION: main` | 主线程发生致命异常（App 崩了） |
| `NullPointerException` | 空指针：用了 null 对象 |
| `on a null object reference` | 在一个 null 对象上调用方法 |
| `at com.yzc.bookmall.ui.BookDetailActivity.bindBook(...:142)` | **问题在第 142 行** |
| `at android.os.Handler.handleCallback` | 系统内部调用（忽略） |

**双击那一行，Android Studio 会直接跳到出错的代码位置。**

### 这个例子的问题在哪

`BookDetailActivity.bindBook(book)` 里 `book.getTitle()` 报空指针，说明传进来的 `book` 是 `null`。

往上追：`load()` 里

```java
book = repository.getBookById(bookId);
if (book == null) {
    stateView.showError("这本书已下架");
    return;        // ← 有这行就不会崩
}
bindBook(book);
```

如果代码里漏了 `if (book == null) return;`，就会崩。

> **项目里所有 `getBookById` / `getStoreById` / `getOrder` 后面都跟着 null 判断**，就是为了防这个。

## 14.3 五种最常见的崩溃

### ① `NullPointerException`（空指针）

**原因**：对 `null` 调用了方法。

**项目里的高发场景**：

```java
// ❌ 危险
Book book = repository.getBookById(999);   // 不存在的 ID，返回 null
book.getTitle();                            // 崩

// ✅ 项目里的做法
if (book == null) {
    stateView.showError("这本书已下架");
    return;
}
```

**怎么防**：任何可能返回 `null` 的方法（查数据库、`findViewById`），调用后都要判空。

### ② `ActivityNotFoundException`

**原因**：跳转的目标 Activity 没在 `AndroidManifest.xml` 里登记。

```
android.content.ActivityNotFoundException:
    Unable to find explicit activity class
    {com.yzc.bookmall/com.yzc.bookmall.ui.XXXActivity};
    have you declared this activity in your AndroidManifest.xml?
```

**报错信息已经告诉你答案了**：去 Manifest 里加一行 `<activity android:name=".ui.XXXActivity" />`。

### ③ `IndexOutOfBoundsException`（越界）

**原因**：访问了列表里不存在的下标。

```java
List<Book> books = repository.getAllBooks();   // 假设只有 20 条
books.get(20);                                  // 崩！下标是 0~19
```

**项目里的高发场景**：Adapter 的 `position`。

```java
// ❌ 危险：position 可能超出 items 范围（数据刚被清空时）
Book book = items.get(position);

// 项目的做法：用 submit() 统一更新，保证 items 和 UI 一致
```

### ④ `IllegalStateException`

**原因**：状态不对。**这个异常项目里是主动抛的**，用来传递业务错误：

```java
throw new IllegalStateException("库存不足：" + item.getTitle() + "（仅剩 " + current.getStock() + " 本）");
```

```java
// CheckoutActivity 捕获它并弹窗
} catch (IllegalStateException e) {
    new AlertDialog.Builder(this)
            .setTitle("提交失败")
            .setMessage(e.getMessage())
            .show();
}
```

> **这是个好设计**：数据层用异常表达"业务失败"，界面层负责翻译成人话。数据层不需要知道怎么弹窗。

### ⑤ `SQLiteException`

**常见信息**：

| 报错 | 原因 |
|---|---|
| `no such table: xxx` | 表没建（`onCreate` 没执行或被跳过） |
| `no such column: xxx` | 列名写错，或忘了升级数据库版本 |
| `UNIQUE constraint failed` | 违反唯一约束（用户名重复、订单号重复） |
| `FOREIGN KEY constraint failed` | 外键指向的记录不存在 |

**最坑的是 `no such column`**：你改了建表语句，但数据库已经存在，`onCreate` 不会重跑。**解决办法：把 `DATABASE_VERSION` +1，或卸载重装。**

## 14.4 断点调试：比 Log 更强大

**步骤**：

1. 在代码行号左边**点一下**，出现红点（断点）
2. 点工具栏的**虫子图标**（Debug）而不是三角形
3. App 跑到那一行会**暂停**
4. 底部出现 Debug 面板，能看到**所有变量的当前值**
5. 按 `F8` 单步执行（Step Over），`F7` 进入方法（Step Into）
6. 按 `F9` 继续运行

**什么时候用断点？**

- 想知道某个变量到底是什么值（比加 `Log.d` 方便）
- 想知道代码走了哪个分支
- 想一步步看数据怎么变的

**新手最有用的一招**：在 `onCreate` 第一行打断点，然后一步步 `F8`，看程序到底走到哪一步出问题。

## 14.5 看数据库里到底存了什么

**方法一：Device Explorer（推荐）**

1. View → Tool Windows → **Device Explorer**
2. 展开 `data/data/com.yzc.bookmall/databases/`
3. 右键 `book_mall.db` → **Save As** 保存到电脑

1. View → Tool Windows → **App Inspection**
2. 选 **Database Inspector**

**什么时候需要？**

- "为什么订单金额不对？"→ 看看 `orders` 表的 `total_amount_fen`

## 14.6 项目常见问题 FAQ

### Q1：改了 `books.json`，重新运行没变化

**原因**：数据库已存在，`onCreate` 不会再执行。

**解决**（三选一）：
1. 卸载 App 重装
2. 把 `BookDbHelper.DATABASE_VERSION` 从 3 改成 4（会走 `onUpgrade`）
3. 用 Device Explorer 删掉 `book_mall.db`

### Q2：首页一片空白，没有书店

**排查顺序**：

1. Logcat 有没有红色错误？
2. `stores` 表有数据吗？（Database Inspector）
3. `HomeFragment.loadNow()` 里 `stores.isEmpty()` 走了哪个分支？
4. `stateView` 显示的是"加载中"还是"空"？

**最常见原因**：`JsonSeeder` 解析失败走了 `fallback()`，只插了 1 家店。

### Q3：点登录没反应

**排查**：

```java
long userId = repository.authenticate(username, password);
if (userId < 0) {
    passwordInput.setError(getString(R.string.error_login_failed));
    return;      // ← 有没有这行？
}
```

如果 `setError` 没显示，可能是 `EditText` 被 `TextInputLayout` 包着，`setError` 要设在 `TextInputLayout` 上才明显。

### Q4：购物车合计一直是 ¥0.00

**排查**：

1. 有没有勾选商品？（没勾选合计就是 0）
2. `adapter.getSelectedTotalFen()` 返回多少？（打断点看）
3. `CartItem.getSubtotalFen()` 里 `priceFen` 是不是 0？（数据库里价格存对了吗）

### Q5：提交订单提示"库存不足"，但明明有货

**原因**：购物车里的数量是**上次加载时**的，库存可能已经变了。

**项目的行为是正确的**：`createOrder` 会重新查库存。如果你之前测试时下过单，库存真的减少了。

**验证**：去 Database Inspector 看 `books.stock`。

### Q6：界面被状态栏挡住

**原因**：`targetSdk 36` 强制边到边，没处理 insets。

**项目已经统一处理了**：所有 Activity 继承 `BaseActivity`，`onCreate` 里调 `applyInsets(...)`。

**如果你新加了一个 Activity**，记得：

```java
setContentView(R.layout.activity_xxx);
applyInsets(findViewById(R.id.root));    // ← 别忘了这行
```

### Q7：深色模式下文字看不清

**原因**：项目**锁定为浅色主题**（`Theme.MaterialComponents.Light`），如果手机开了深色模式但界面还是浅色，说明主题配置被改了。

**检查**：`res/values/themes.xml` 和 `res/values-night/themes.xml` 的 `parent` 是不是 `Light`。

## 14.8 答辩准备：15 个高频问题

老师最可能问这些，提前想好答案。

### 架构类

**Q1：为什么分 model / data / ui / util 四层？**
> 职责分离。界面只管显示，数据只管存取，实体只描述结构。改一处不影响其他层，也方便多人协作。

**Q2：Repository 和 DbHelper 有什么区别？**
> Helper 管"数据库本身"（建表、升级），Repository 管"业务需求"（取书店、下单）。所有 SQL 集中在 Repository，界面层看不到 SQL。

**Q3：为什么不用 Room 而用原生 SQLite？**
> 课程要求体现 SQL 和建表过程。Room 是 ORM 框架，会屏蔽 SQL 细节，不适合教学演示。而且原生 SQLite 零依赖，离线构建稳定。

### 数据类

**Q4：为什么金额用 int 存"分"？**
> 浮点数有精度误差（0.1+0.2≠0.3）。用整数存分，加减乘除都精确，展示时再除以 100。

**Q5：订单明细为什么要存书名和价格快照？**
> 书可能改价或下架。只存 book_id 的话，用户半年后看订单会看到"现在的价格"。存快照保证历史订单不变。

**Q6：什么是事务？项目哪里用了？**
> 事务保证一组操作"要么全成功，要么全失败"。下单时用了：检查库存 → 写订单 → 写明细 → 扣库存 → 清购物车，任一步失败全部回滚，避免超卖。

**Q7：数据库升级怎么做的？**
> 用 `onUpgrade` 做增量迁移：加表、加列，然后 update-or-insert 刷新目录数据。**不删表重建**，因为会丢失用户数据，还会触发外键级联删除。

### 界面类

**Q8：RecyclerView 为什么比 ListView 好？**
> 强制使用 ViewHolder 模式（缓存控件引用），复用机制更完善，支持局部刷新和动画。

**Q9：为什么用 Fragment 而不是四个 Activity？**
> 底部导航栏只写一次，切换时不重建整个页面，返回栈行为更合理（不会出现"退回上一个 Tab"）。

**Q10：`replace` 和 `add` 有什么区别？**
> `replace` 销毁旧 Fragment，省内存但丢状态；`add + hide/show` 保留状态但费内存。项目用 `replace`，因为数据都在 `onResume` 重新查，不怕丢。

**Q11：`StateView` 是干什么的？**
> 统一管理四种状态：加载中、有内容、空、错误。避免白屏，让用户知道发生了什么。

### 安全与规范类

**Q12：登录状态怎么保持的？**
> `SharedPreferences` 存 userId 和 username。启动时读 userId，大于 0 就认为已登录。

**Q13：怎么防止用户看到别人的订单？**
> 所有"查我的数据"的 SQL 都带 `user_id = ?`。比如 `getOrder(userId, orderId)` 同时匹配两个条件。

**Q14：密码是怎么存的？**
> 课程项目为了演示用了明文，**这是已知的局限**。真实项目应该用 bcrypt 加盐哈希，登录时比对哈希值。

> 💡 **主动说出局限，比被问出来好。**

**Q15：这个项目和教材的"网上订餐"比，难度如何？**
> 页面层级一样是三层（店铺→商品→下单），但页面数 17 比 8 多，数据表 12 张比 5 张多，列表全部用 RecyclerView，还多了事务、四态管理、优惠券、评价、地址簿。

## 14.9 学习之后的下一步

学完这个项目，你已经掌握了 Android 开发的基础。接下来可以：

| 方向 | 学什么 | 为什么 |
|---|---|---|
| **语言** | Kotlin | Google 官方首选语言，语法更简洁 |
| **架构** | MVVM + ViewModel + LiveData | 官方推荐架构，解决"配置变更丢数据" |
| **数据库** | Room | 官方 ORM，编译期检查 SQL |
| **网络** | Retrofit + OkHttp | 真实项目都要联网 |
| **异步** | 协程（Kotlin） | 替代 Handler 和线程池 |
| **UI** | Jetpack Compose | 声明式 UI，未来趋势 |

**建议顺序**：Kotlin → MVVM → Room → Retrofit。

**别一次学太多。** 每学一个，就把这个项目的一部分用新技术重写一遍，对比着看差异，理解得最快。
